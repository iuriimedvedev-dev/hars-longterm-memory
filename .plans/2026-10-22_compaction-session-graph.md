# Feature spec: session compaction memory (compaction -> facts -> graph + vectors)

Branch: feat/compaction-session-graph (based on fix/ci-baseline-lint-tests, PR #9)
Status: implementation spec for ninja-coder. Do NOT edit this file.

## Problem

Agent sessions with 10-50 compactions lose everything except a short in-context
summary. Goal: persist each compaction (summary + facts from the dropped context)
into long-term memory as facts, indexed into vectors, so the agent keeps and
enriches them across the session, and so merged knowledge survives the session.

Two hypotheses, both implemented behind one switch:

- mode `split` (HYPOTHESIS B, default; Zep/Graphiti lineage, arXiv:2501.13956):
  each session gets its own isolated LightRAG working dir
  `<sessions_dir>/<session_id>/` (own graphml + Nano vdb + doc status). Merge
  later consolidates into the main index.
- mode `subgraph` (HYPOTHESIS A; Mem0/A-Mem lineage): compaction docs are
  ingested directly into the MAIN index; LightRAG extraction links entities to
  existing graph nodes. Session identity lives in the provenance header and
  file_path.

Merge (split mode): build ONE chronological merged document from all
compaction docs, add entity-alias hints (session graph entities matched to main
graph entities), re-ingest into the MAIN index so LightRAG's own extraction
performs entity resolution (GraphRAG-incremental-style consolidation).
Idempotent via a merge marker. Provenance is preserved by the
`[Document: ... | Section: session | Date: ...]` header (Section: session is
already a recognized section value in memory_forget/cleanup_kb).

## Env vars (defaults inline, same read style as neighbors)

- `HARS_MEMORY_SESSION_MODE`: `split`|`subgraph`, default `split`
- `HARS_MEMORY_SESSIONS_DIR`: default `<HARS_MEMORY_INDEX_DIR>/sessions`
- `HARS_MEMORY_SESSION_INDEX_BS`: int, default 25, clamp 1..256 (compaction
  indexing batch size; also passed as embed batch for session RAGs)
- `HARS_MEMORY_SESSION_MIN_SCORE`: float, default 0.2 (recall session-channel cutoff)

## STEP 1 - hars_memory/session_memory.py (core SessionMemoryStore)

READ FIRST: hars_memory/ingest/api.py (ingest_documents), hars_memory/ingest/document.py
(Document, build_source_header, file_stable_id), hars_memory/ingest/change_detection.py,
hars_memory/server/lightrag_init.py (create_lightrag signature), scripts/cleanup_kb.py
(HEADER_RE), and the memory_upsert_document branch in hars_memory/mcp_server.py
(cache invalidation helpers).

class SessionMemoryStore(index_dir, sessions_dir=None, mode=None, index_bs=None).

- session_id validation: regex ^[A-Za-z0-9._-]{1,128}$ else ValueError (traversal guard).
- `_build_compaction_document(session_id, seq, summary, dropped_context, metadata) -> Document`:
  name `session-<sid>-c<seq>`; header produced via build_source_header so the line is
  EXACTLY three pipe fields: `[Document: session-<sid>-c<seq> | Section: session | Date: YYYY-MM-DD]`
  (must stay byte-compatible with scripts/cleanup_kb.py HEADER_RE; no extra pipe fields).
  Body: `Session: <sid>`, `Seq: <n>`, `Tags: session, compaction`, optional single-line
  `Metadata: <compact json>`, then `## Summary` (summary text), then optional
  `## Dropped context facts` with one `- ` bullet per item (collapse newlines, strip).
  file_path: `sessions/<sid>/compaction-<seq>.md`. Re-ingest of same (sid, seq) must be
  a no-op via the existing fingerprint gate.
- `store_compaction(session_id, summary, dropped_context: list[str]|str|None=None,
  metadata: dict|None=None, seq: int|None=None) -> dict`:
  seq None => next = 1 + max seen; persist `sessions/<sid>/seq.json` atomically
  (tmp+rename), roll back on ingest failure. Target index_dir: split =>
  `sessions/<sid>`, subgraph => main index_dir. CRITICAL: session-dir ingests MUST
  force `NanoVectorDBStorage` + `NetworkXStorage` regardless of env (Qdrant env would
  otherwise collide session data with main collections): extend ingest_documents with
  optional `vector_storage: str|None=None`, `graph_storage: str|None=None` kwargs
  (None = current env-driven behavior, backward compatible). batch_size=index_bs.
  Return `{"ok": true, "session_id", "seq", "doc_id", "mode", "index_dir"}`.
- `merge_session(session_id, delete_source=False) -> dict`:
  subgraph => `{"ok": true, "merged": false, "reason": "subgraph mode indexes compactions directly into the main graph"}`.
  split: missing dir => ValueError; `merged.json` exists => return payload +
  `already_merged: true`. Read session `kv_store_full_docs.json`, order by Seq, build
  merged doc named `session-<sid>-merged`, header
  `[Document: session-<sid>-merged | Section: session | Date: <today>]`, body =
  chronological `## Compaction <n>` sections (summary + dropped facts), then
  `## Entity aliases`: load main + session graphml node ids via networkx (fail-soft
  empty), normalized-name exact matches plus difflib.get_close_matches(cutoff=0.92),
  lines `<session_name> -> <main_name>`. ingest_documents([merged], index_dir=MAIN,
  batch_size=index_bs). On success write merged.json `{merged_at, compactions, chars,
  alias_hints, merged_doc_id, delete_source}`; if delete_source rmtree the session dir.
  Invalidate the same caches memory_upsert_document invalidates (lazy import to avoid cycles).
- `session_status(session_id=None) -> dict`: no arg => `{"sessions": [...]}`
  (session_id, compactions, merged, merged_at, entities, relations, index_dir);
  with arg => single detail. All stats fail-soft (corrupt/missing files => zeros).
- Module docstring: explain both modes + research lineage. Type hints, logging not
  prints, stdlib only, ruff 0.14.13 clean.

## STEP 3 - memory_recall session channel (unmerged sessions, split mode)

Add optional `session_id` arg to memory_recall. When set AND mode=split AND session
NOT merged (merged.json absent): build a session channel following the ripgrep
channel pattern (READ the ripgrep implementation first: appended, never evicting,
ids prefixed like `ripgrep:`).

- Parse session `kv_store_text_chunks.json`; embed the query with the SAME embedding
  func the recall path already uses; cosine-score against session `vdb_chunks.json`
  matrix (NanoVectorDB json: embedding_dim, data[{__id__,...}], matrix = base64 zlib
  float16; rows align with data order; numpy is already a dep). ALSO lexical
  case-folded token-set F1 per chunk. final score = max(cosine, lexical_f1); drop
  below HARS_MEMORY_SESSION_MIN_SCORE (default 0.2); top fetch_top_k.
- Inject appended-never-evicting like ripgrep, ids prefixed `session:<sid>:`.
  Extend FusedChunk (hars_memory/retrieval/fusion.py) with optional
  `channel: str|None = None` and `session_id: str|None = None` (defaults keep all
  existing construction sites valid).
- Emit `session_hits` trace frame (style of bm25_hits/vector_hits). Response gains a
  `session` block `{"session_id", "hits", "merged": false}` and echoes session_id at
  top level when provided.
- Merged or subgraph mode: skip channel, session block explains why
  ({"session_id", "hits": 0, "merged": true} or a skipped-reason). Missing session
  dir: session block {"error": "unknown session"}; recall still succeeds. Channel is
  fail-soft everywhere (log + empty hits). Lean view + compact must not crash on new
  fields. No default behavior change when session_id absent. ruff clean.

## STEP 5 - simulation script + config docs

hars_memory/scripts/session_compaction_sim.py (python -m
hars_memory.scripts.session_compaction_sim; structure/logging like other scripts in
hars_memory/scripts/). CLI: --session (default "sim-session"), --compactions N
(default 30), --mode split|subgraph (default env), --merge, --out DIR (sim_report.json
+ printed table), --live.

- Default (no --live): hermetic stub mode - replace the ingest call with an in-memory
  recorder; deterministic synthetic compaction texts (fixed seed; each summary
  references 2 entities shared across compactions + 1 unique; dropped context = 3
  bullet facts). Stats: docs, per-compaction wall time, batch grouping (bs=25
  whenever >25 queued in one flush), merge output size, alias candidate count
  (difflib against a fixed main-entity list).
- --live: real SessionMemoryStore against env dirs (requires extractor/embedder env;
  manual verification only).
