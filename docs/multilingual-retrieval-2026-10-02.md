# Мультиязычный поиск: эксперименты M1-M7 и opt-in маршрутизация (2026-10-02)

## TL;DR
- Проблема подтверждена: на eval v2 (345 кейсов) baseline (gemma+BM25) даёт fact@5 .489 для ru-вопроса -> en-док против .778 для en->en (разрыв ru-en на en-доках -0.22); en-вопрос -> ru-док тоже слабый (.533).
- Главный рычаг выравнивания: английский «двойник» запроса от LLM, склеенный с оригиналом (`orig + twin`) в 3-канальной fusion gemma+qwen3+BM25: ячейка a .489 -> .711 (+.222 [+.111,+.356]*), overall .745 -> .809 (+.064*), разрыв -0.22 -> -0.07. Цена: ~2.2 с и ~$0.00006 на ru-запрос.
- Qwen3-Embedding как единственный dense лучше gemma (.667 vs .600 overall), но в гибриде с BM25 выигрыш внутри шума; 3-way fusion (веса .2/.4/.4) +0.035 [+.006,+.067]* overall, по ячейкам шум. RRF хуже взвешенной fusion.
- Reranker (HTTP Qwen3-Reranker) даёт самый большой прирост (3-way: .780 -> .846; rrf2_3way .774 -> .881), но на нагруженной машине 13 с медиана; встроенного (in-process) reranker офлайн нет.
- Маршрутизация по языку НЕ лучше лучшего единого профиля по качеству (CV-routed .878 vs best global .881, внутри шума); её ценность — экономия: en-запросы идут без LLM (медиана 0.3 с вместо 2.2 с) без потери качества.
- Реализовано opt-in: `HARS_MEMORY_ROUTING=lang` (en: 3way; ru/mixed: 3way_twin) + sidecar Qwen3 (`memory build-dense-sidecar`). Прод-путь на клоне, off -> lang: overall .774 -> .800 (+.026 [-.006,+.058]), ячейка a +.200 [+.067,+.333]*, разрыв ru-en -0.196 -> -0.071.
- Рекомендация: `HARS_MEMORY_ROUTING=lang` (+ при стабильной инфраструктуре `HARS_MEMORY_RERANK_BACKEND=http`). Дефолты пакета не изменены.

## Данные и метод
Индекс: клон /tmp/search-exp/ml-clone (мигрированный /tmp/eval-mig/after, 4168 чанков); живой индекс не трогался. Код: experiments/search-2026-10/ml/ (`python compact.py M5 [fact_rr]`, `report_md.py M5` печатают таблицы и CI из ml/results/).
Eval v2 (cases_ml.yaml): 225 кейсов gpt-6-luna, gold_fact проверен дословно в файле и внутри одного чанка; плюс 120 старых (регрессия: old_ru n=42, old_en n=78). Ячейки (n=45): a ru-вопрос -> en-док; b en->en (a и b парные по pair_id); c ru->ru/mixed-док; d en->ru/mixed-док; e ru-текст + латинский идентификатор.
Шум: при n=45 полуширина 95% bootstrap-CI по fact@5 около +-0.13 (n=42..78: +-0.10, overall n=345: +-0.04); разности меньше CI считаем шумом, `*` = CI исключает 0 (парный bootstrap). Новые кейсы труднее старых (нет подсказок-идентификаторов, много conceptual). Метрики: fact@5, fact_rr (MRR по top-20). Офлайн-профили считаются из кэша кандидатов (top-100/канал), fusion: min-max weighted (alpha .5, pool 15 для 2 каналов; 3-way pool 15-20).

## Вердикты
- M1 baseline: разрыв ru/en реален (a vs b: .489 vs .778). Потолок recall top-100 по объединению каналов в ячейке a только .844 (в остальных ~1.0) — часть фактов недостижима без смены запроса. CONFIRMED.
- M2 Qwen3 как единственный dense: CONFIRMED на уровне dense (.667 vs .600 overall, значимо в b/e); в гибриде с BM25 +.023 overall — INCONCLUSIVE (шум). Усечение чанков 512 vs 1024 токенов без разницы (при 1024 в 1.2 раза медленнее) — оставлено 512.
- M3 equalize fusion gemma+qwen+BM25: +.035 [+.006,+.067]* overall, по ячейкам шум; 2-fold CV по pair_id выбирает равные/близкие веса (.2/.4/.4 в целом лучший). Слабый CONFIRMED. RRF (k20/k60): REFUTED (хуже взвешенной).
- M4 русский BM25 (суффиксный стеммер, латиница без изменений — проверено тестом на 200 чанках): CONFIRMED для ru-доков (c: +.378 [+.22,+.53]*), нейтрален на en-ячейках, слегка вреден для ru-запросов к en-докам (a -.067, old_ru -.095 [CI на границе]: кириллические основы подтягивают ru-доки). В гибриде overall +0.00..+0.006 — INCONCLUSIVE; в фичу не включён.
- M5 кросс-язычный twin (gpt-6-luna): concat (orig+twin) CONFIRMED: a +.222*, d +.111, overall +.064* (base) / +.029 (к 3way_orig); twin-only REFUTED как глобальный профиль (b -.156*), RRF orig/twin хуже concat. Стоимость $0.00006/запрос, медиана 1.9 с (p95 3.5 с).
- M6 reranker: CONFIRMED, самый сильный рычаг (overall +.066..+.107 к первой стадии; особенно d и c). Латентность: 2.3 с медиана без нагрузки (H11), 13 с медиана на загруженной машине (сервис общий с другим проектом). In-process reranker офлайн недоступен (в HF-кэше нет cross-encoder/reranker), поэтому reranker остаётся отдельным opt-in `HARS_MEMORY_RERANK_BACKEND=http`.
- M7 маршрутизация по языку (определение: доля кириллицы, точность 99.7% = 344/345; промах — португальский вопрос): лучшая пара (en,ru) по CV = тот же единый профиль; routed vs best global -.003 [-.009,0] — шум. «Дешёвый» routing en:3way / ru:concat даёт .797 vs global concat .809 (шум) при экономии LLM-вызова на en (медиана en 0.3 с вместо 2.2 с). Вердикт: роутинг как улучшение качества REFUTED, как оптимизация цены/латентности CONFIRMED.
- M7b языковой prior по чанкам (буст чанков языка запроса): +.003 (match) / -.012..-.018 (opposite) — REFUTED/шум; не реализован.
- Выравнивание (разрыв ru-en на en-доках, mean(a,old_ru) - mean(b,old_en)): base -0.219; 3way -0.178; 3way concat -0.070; + rerank -0.061; rrf2_3way+rerank -0.038.

Traffic-weighted fact@5 (допущение: 50% ru-запросов; из ru 90% к en-докам [a,e,old_ru] и 10% к ru-докам [c]; из en 95% к en-докам [b,old_en] и 5% к ru [d]): base .774 [.728,.818]; 3way .811; 3way concat .836 [.795,.877]; concat+rerank .886 [.850,.922]; routed en:3way/ru:concat .834; best global (rrf2_3way+rerank) .885.

## Рекомендуемый профиль
`HARS_MEMORY_ROUTING=lang` с дефолтами (en: gemma+qwen3+BM25 .2/.4/.4; ru/mixed: то же + английский twin, склеенный с запросом). Поверх — по готовности инфраструктуры `HARS_MEMORY_RERANK_BACKEND=http` (+0.07 overall, ru-en разрыв до -0.04..-0.06, но +2.5..13 с). Без sidecar/модели/LLM система тихо откатывается к текущему поведению (поле `routing.fallback_reason`).
Стоимость/латентность: en +0.2 с, ru +2.1 с (LLM) и $0.00006; память: Qwen3-0.6B fp16 в процессе (~1.2 ГБ), sidecar ~17 МБ на 4168 чанков (float16, 1024-d).

## Оговорки
- Потолок точности — малые n: по ячейкам CI +-0.13, поэтому кроме a (ru->en) и агрегатов все различия — направления, а не доказательства.
- Кейсы сгенерированы LLM (gpt-6-luna), перевод ru-вопросов тоже LLM -> может быть «слишком вежливый» перевод; реальные запросы агентов короче/грязнее.
- Веса трафика в traffic-weighted — допущение; реальная доля ru-запросов и ru-доков неизвестна.
- Reranker-латентность сильно зависит от соседей по машине; concat+rerank оценён по неполному кэшу скоров.
- Sidecar не обновляется инкрементально; требует пересборки после инжеста (иначе откат по coverage).
- Языки кроме ru/en (например португальский) определяются как en (1 кейс из 345).
- Старая known bug battle.py/_PROJECT_ROOT не затрагивалась.
